# TEHNO CENTER 2

Интернет-магазин и CRM на React, TypeScript и Supabase.

## Запуск

```bash
npm install
npm run dev
```

Требуется Node.js 22+. Настройки публичного подключения к Supabase находятся в
`.env.local`; service-role ключ в браузерный код не добавляется.

## Проверка

```bash
npm run check
npm run test:e2e
```

`npm run check` запускает TypeScript, 44 модульных/компонентных теста и
production-сборку. Для `test:e2e` должен быть установлен Chromium Playwright.

Транзакционная проверка серверной цепочки находится в
`supabase/tests/supplier_product_finance_flow.sql`: она создаёт поставщика,
две модели, товары, наличный и рассрочный заказы, проверяет склад, долги и
комиссии, после чего откатывает все тестовые данные.

## Поставки и создание товаров

Новая карточка товара создаётся только из принятой строки поставки:

1. В разделе «Поставщики» создайте поставщика и добавьте одну или несколько
   моделей с количеством и закупочной ценой.
2. В разделе «Каталог» выберите поставщика и точную модель из поставки.
3. Укажите цену продажи и комиссию менеджера — процент или фиксированную сумму
   за штуку. Приход на склад и связь с поставщиком создаются одной транзакцией.

Удаление товара является безопасным: карточка сразу исчезает с сайта, а история
продаж, финансов и складских движений сохраняется.

Удаление поставщика также является мягким: он сразу исчезает из рабочего списка
и больше не может использоваться для новых поставок или товаров. Старые товары,
себестоимость, долги и история продаж при этом сохраняют связь с поставщиком.

Вместо двух дублирующих редакторов у товара осталось одно многострочное поле
«Характеристика». Для совместимости существующее JSONB-поле
`products.specifications` сохраняется пустым, поэтому миграция базы не нужна.
В форме создания товара есть отдельный поиск поставщика по названию, контакту
или телефону и поиск строки поставки по товару, бренду или модели. Публичная
карточка товара поддерживает быстрый свайп, стрелки, точки прогресса и
полноэкранный просмотр фотографий с клавиатурой и миниатюрами.

Покупательская часть оформлена как компактный мобильный маркетплейс: заметный
поиск, быстрые категории, светлые товарные карточки, оранжевый акцент,
двухколоночный каталог на телефоне и нижняя мобильная навигация.

SQL этой архитектуры находится в миграциях
`20260813150000_supplier_deliveries_product_flow.sql`,
`20260813160000_fix_product_delete_audit_action.sql` и
`20260813170000_harden_supplier_flow_rpc_permissions.sql`, а положительная
закупочная цена закреплена миграцией
`20260813180000_require_supplier_delivery_purchase_price.sql`. Исправление
удаления поставщика находится в
`20260813190000_fix_supplier_archival.sql`.

## Логика курьерской доставки

Основной путь заказа:

`Новый → В работе → Подтверждён → Курьер забрал → Курьер в пути → Завершён`.

- При подтверждении товар резервируется.
- Когда курьер забрал товар, он списывается со склада, а выкуп отмечается как
  ожидающий и не попадает в выручку.
- Только «Завершён» создаёт оплату, выручку, себестоимость, долг поставщику и
  комиссию менеджеру.
- При отказе или отмене выданный товар возвращается на склад, а ожидающий выкуп
  помечается возвращённым.

SQL находится в `supabase/migrations/20260813010000_courier_lifecycle.sql`.
Серверная функция приглашения менеджеров находится в
`supabase/functions/invite-manager/index.ts`.
